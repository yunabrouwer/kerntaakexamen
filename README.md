# TableTalk

TableTalk is a PHP 8.2+ and MySQL feedback application for restaurant guests and managers.

## Requirements

- PHP 8.2 or newer with PDO MySQL and mbstring enabled
- MySQL 8.0 or newer
- A web server with PHP support, or PHP's built-in development server

## Installation

1. Create the database and tables by running `schema.sql` with a MySQL account allowed to create databases.
2. Configure the database connection with environment variables:
   - `TABLETALK_DB_HOST` (default: `127.0.0.1`)
   - `TABLETALK_DB_NAME` (default: `tabletalk`)
   - `TABLETALK_DB_USER` (default: `root`)
   - `TABLETALK_DB_PASSWORD` (default: empty)
3. Create an active establishment and a manager account. Generate a password hash with:

   ```sh
   php -r "echo password_hash('Choose-a-strong-password', PASSWORD_DEFAULT), PHP_EOL;"
   ```

   Insert the establishment first, then use its ID and the generated hash:

   ```sql
   INSERT INTO vestigingen (naam) VALUES ('Restaurant Voorbeeld');
   INSERT INTO admins (vestiging_id, naam, email, wachtwoord_hash)
   VALUES (1, 'Manager', 'manager@voorbeeld.nl', 'PASTE_THE_GENERATED_HASH_HERE');
   ```

   Replace the sample values and hash. Never use a sample password as an actual manager password.
   Set `actief` to `0` on a `vestigingen` or `admins` row to disable it.
4. Serve the project directory as the web root. For local development and access from other devices on the same network, run:

   ```sh
   php -S 0.0.0.0:8000
   ```

   Binding to `0.0.0.0` makes the development server listen on the computer's network interfaces. If using XAMPP, start Apache instead; its default document root is `C:\xampp\htdocs`.

5. On the computer running the server, open `http://127.0.0.1:8000/?vestiging_id=1`. On another device connected to the same Wi-Fi or LAN, use the server computer's local IPv4 address instead of `127.0.0.1` or `localhost`, for example `http://192.168.1.25:8000/?vestiging_id=1`. Find that address with `ipconfig` on Windows. With XAMPP's default Apache port, use `http://192.168.1.25/kerntaakexamen/?vestiging_id=1` instead. Without a `vestiging_id`, guests can choose an active establishment. Managers sign in at `/login.php` with their email address and can open `/qr-codes.php` to print a QR code for their own establishment.

   If the other device cannot connect, allow the PHP development server or Apache through Windows Firewall on the private network and confirm both devices are on the same network. Do not expose the development server directly to the public internet.

For QR codes scanned by guests on another device, set `TABLETALK_BASE_URL` to a URL reachable by those devices, including its path if the app is installed in a subdirectory. For LAN use, that can be `http://192.168.1.25:8000` (or `http://192.168.1.25/kerntaakexamen` with XAMPP); for production, use the public HTTPS URL, for example `https://example.nl/tabletalk`. If it is not set and the manager opens the site via `localhost`, the QR page tries to use a network address for the server instead; if it cannot determine one, configure `TABLETALK_BASE_URL`. Localhost addresses are rejected so the QR code is not generated with a link that only works on the server computer. QR images are generated by QRServer, which receives the survey URL.

## Existing databases

`CREATE TABLE IF NOT EXISTS` does not add columns to tables that already exist. If the database was created from an older version of this repository's `schema.sql`, first migrate its `vestigingen.slug`, `admins.gebruikersnaam`/`password_hash`, and `feedback.beschrijving` columns. Replace the example email with a real, unique manager email for each account:

```sql
UPDATE admins SET gebruikersnaam = 'manager@example.nl' WHERE id = 1;
ALTER TABLE vestigingen
    ADD COLUMN actief TINYINT(1) NOT NULL DEFAULT 1,
    MODIFY slug VARCHAR(120) NULL;
ALTER TABLE admins
    CHANGE COLUMN gebruikersnaam email VARCHAR(255) NOT NULL,
    CHANGE COLUMN password_hash wachtwoord_hash VARCHAR(255) NOT NULL,
    ADD COLUMN actief TINYINT(1) NOT NULL DEFAULT 1;
ALTER TABLE feedback
    CHANGE COLUMN beschrijving toelichting TEXT NOT NULL;
```

Then, for any existing installation, add the unique submission token. Existing feedback records are retained:

```sql
ALTER TABLE feedback
    ADD COLUMN submission_token CHAR(64) NULL;
UPDATE feedback
    SET submission_token = SHA2(CONCAT('legacy-', id), 256)
    WHERE submission_token IS NULL;
ALTER TABLE feedback
    MODIFY submission_token CHAR(64) NOT NULL,
    ADD UNIQUE KEY uq_feedback_submission_token (submission_token);
```

The former JSON records in `feedback.txt` are not imported automatically; keep that file as a backup if you need those records.

## User flows

- Guest surveys are only served for active establishments. The server validates required fields and rechecks the establishment when saving. Prepared statements store feedback in MySQL, and a unique submission token plus a disabled submit button limits duplicate submissions.
- Manager accounts use password hashes, active-account checks, session expiry after 30 minutes of inactivity, and a vestiging association. The dashboard and detail endpoint scope every feedback query and status update to the manager's own establishment.
- The guest form retains valid input after validation errors. Database errors are shown as a retryable generic error; manager login errors do not reveal whether an account exists.

Use HTTPS in production so session cookies are transmitted securely. Configure database credentials through the environment rather than committing them to the project.
